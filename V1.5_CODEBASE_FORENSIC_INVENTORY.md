# InteriorPro V1.5 - Forensic Codebase Inventory

## 1. Project Structure
- `app/src/main/java/com/example/ui/` - Contains all Compose UI screens and ViewModels.
- `app/src/main/java/com/example/data/` - Contains Room Database, Entities, DAOs, and Repositories.
- `app/src/main/java/com/example/engine/` - Contains Calculation Engines (Tax, Quotations).
- `app/src/main/java/com/example/pdf/` - Contains PDF Generator and extension functions.
- `app/src/main/java/com/example/utils/` - Contains Utility classes (Currency Formatting, Validations, Images).
- `app/src/main/java/com/example/core/` - Contains Backup, Sync, Device Management, Drive integration.
- Root scripts (`*.py`, `*.txt`) - Contains numerous Python scripts for patching/replacing files.

## 3. Architecture Map
**Current Actual Architecture (Not Clean):**
```
OS -> MainActivity (Navigation)
      |-> UI Screens (Compose) <-> ViewModels
          |-> Direct inline logic (e.g., NewQuotationScreen calculating totals)
          |-> QuotesRepository / MasterRepository
              |-> Daos
                  |-> Room Database (Entities)

PdfGenerator <- UI Screens (Called directly to render)
                 |-> QuotationCalculationEngine (Recalculates values for rendering)
```

## 6. PDF Forensic Map
- **File**: `PdfGenerator.kt` (1736 lines, monolithic).
- **Functions**: `drawHeader`, `drawCustomerDetails`, `drawItemTable`, `drawSummaryAndPayment`, `drawSignature`, `drawFooter`.
- **Issues**: Tightly coupled, draws coordinates manually using `PdfEngine` (inner class), recalcs some item quantities directly, mixes UI sizing with business logic.

## 7. Patch / Legacy Forensic Audit
There are over 100 Python (`.py`) and text (`.txt`) files in the project root (`patch_pdf_signature.py`, `fix_components.py`, `build_errors.txt`, etc.).
- **Purpose**: Used for hot-fixing bugs, replacing braces, patching PDF layout.
- **Risk**: Clutters the workspace, implies the codebase is fragile and required manual sed/regex patching to stay compiling.
- **Action**: All `.py` and `.txt` patch files must be REMOVED LATER.

## 8. Database Forensic Map
- **Entities**: `CompanyProfile`, `CustomerEntity`, `MasterEntity`, `QuotationTemplate`, `Quotation`, `QuotationItem`.
- **JSON Usage**: `QuotationTemplate.itemsJson` stores data as JSON instead of relational tables.
- **Risk**: Medium. Schema is flat but functional.

## 9. UI / ViewModel Map
- `NewQuotationScreen.kt` handles immense state locally and contains complex business logic inline.
- Navigation is centralized in `MainActivity.kt` but lacks a dedicated router/navigator structure.

## 10. Test Coverage Audit
- `QuotationCalculationEngineTest.kt` - Covers basic unit tests for Sq.Ft, Sq.M, Cu.Ft etc.
- `ExampleRobolectricTest.kt` - Robolectric database tests.
- **Missing Tests**: Missing UI tests, missing PDF data preparation tests, missing comprehensive View Model tests.

## 11. Final Classification

### KEEP
- `com.example.core.*` (Backup & Sync logic is isolated and robust)
- `com.example.utils.*` (Formatters, Managers)
- `Daos.kt`, `AppDatabase.kt`, `Entities.kt` (Core Data Layer)
- Tests (`app/src/test/`)

### REWRITE
- `PdfGenerator.kt` (Must be modularized into a Clean PDF Engine)
- `NewQuotationScreen.kt` (Needs decomposition into smaller UI components)
- `MainActivity.kt` (Navigation needs moving to a dedicated graph)

### REFACTOR
- `QuotationCalculationEngine.kt` (Needs to be the *single* source of truth for all modules)
- ViewModels (Move business logic into explicit Use Cases)

### REMOVE LATER
- All `*.py` and `*.txt` patch scripts in root directory.
- `TestFile.kt`, `TestFile2.kt` in `ui/`.
